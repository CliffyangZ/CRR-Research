# Feature Specification: 單顆牙齒 ROI 分割資料集

**Feature Branch**: 沿用目前分支；本次未建立分支

**Created**: 2026-10-12

**Status**: Ready for planning

**Input**: User description: "003 準備單顆牙齒 ROI 分割資料集。ROI 來源 data/detection_dataset（YOLO tooth 偵測框），分割標籤來源 data/seg_dataset（COCO tooth 多邊形，Metal 不獨立成類）；偵測框與多邊形不一致，須配對最高 IoU 且超過門檻者，ROI 標籤只含目標牙，配對失敗或歧義者隔離；框外擴 10% 後等比例 letterbox 成 256×256；影像前處理只用 CLAHE；增強與 Spec1 相同；沿用既有切分；只產出資料集與驗證報告，不訓練模型。"

## Clarifications

### Session 2026-10-12

- Q: 偵測框與多邊形對不上時，ROI 標籤怎麼定？ → A: 每個偵測框配對 IoU 最高的 tooth 多邊形（設最低門檻），ROI 只標該顆牙，鄰牙為背景；配對失敗者隔離並記錄。
- Q: ROI 如何裁切與輸出？ → A: 偵測框外擴 10% 後裁出，再等比例 letterbox 成 256×256。
- Q: 「外擴 10%」、越界處理與最小遮罩門檻是否採規劃預設？ → A: 使用者確認：每側各外擴框寬／高的 10%（總邊長 ×1.2）；越界部分補灰值 114（遮罩補 0）並記錄補足量；最小遮罩占比預設 5%，建置報告列出實際分布，凍結前僅可依 train／val 調整。
- Q: 偵測框以外是否另有決定？ → A: 影像前處理僅 CLAHE；增強沿用 Spec1，並沿用 spec 002 的「目標牙新增截斷即取消幾何變換」規則。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 取得可信的框—遮罩配對 (Priority: P1)

研究人員能確認每個納入的 ROI 都由一個偵測框與唯一一顆 tooth 多邊形配對而成，不確定的配對被隔離而非猜測。

**Why this priority**: 兩個來源的框與多邊形並不一致，配對錯誤會直接汙染標籤。

**Independent Test**: 以框與多邊形一致、框偏移、同圖多牙相鄰、框無對應多邊形、一個多邊形被多個框競爭五類案例，核對配對結果與隔離原因。

**Acceptance Scenarios**:

1. **Given** 偵測框與 tooth 多邊形，**When** 配對，**Then** 每個框得到 IoU 最高且達門檻的多邊形，並記錄 IoU、次佳 IoU 與配對狀態；一個多邊形至多配給一個框。
2. **Given** 無對應多邊形、IoU 低於門檻、最佳與次佳過於接近或多框競爭同一多邊形，**When** 配對，**Then** 該框被隔離並記錄原因，不進入資料集，不被當作背景樣本。
3. **Given** 兩個來源的影像清單，**When** 盤點，**Then** 影像一一對應且子集一致，不一致者列出；產出各子集框數、多邊形數、納入與隔離數。

---

### User Story 2 - 產生 ROI 影像與單牙遮罩 (Priority: P2)

研究人員能取得每顆牙一組 256×256 的 ROI 影像與二元遮罩，並可追溯回原圖座標。

**Why this priority**: 這是資料集本體，依賴 US1 的配對。

**Independent Test**: 以控制點與已知遮罩核對裁切、letterbox 與還原，並核對遮罩只含目標牙。

**Acceptance Scenarios**:

1. **Given** 已配對的框，**When** 外擴 10% 並裁切（超出影像處以背景補足並記錄），**Then** 等比例縮放補邊成 256×256，遮罩只含目標牙多邊形（Metal 不獨立成類、鄰牙為背景），標籤值僅 0／1。
2. **Given** ROI 紀錄，**When** 將 ROI 座標還原，**Then** 回到原圖座標的控制點誤差每軸不超過 1 個原圖像素。
3. **Given** 影像，**When** 前處理，**Then** 僅套用固定 CLAHE（不用 NLM 與 USM），且不改動遮罩；非 8-bit 影像先隔離。

---

### User Story 3 - 防洩漏切分與訓練專用增強 (Priority: P3)

研究人員能取得沿用既有子集且無洩漏的資料集，並確認增強只作用於訓練 ROI。

**Why this priority**: 完成後資料集即可供後續分割訓練，但需先有 US1、US2。

**Independent Test**: 核對同圖 ROI 同子集、跨子集近重複為零，並以七類案例核對增強規則。

**Acceptance Scenarios**:

1. **Given** 既有 train／val／test 與 ROI，**When** 檢查，**Then** 同一張原圖的所有 ROI 在同一子集，近重複與跨子集洩漏檢查結果被記錄；確認洩漏時修正並凍結新清單。
2. **Given** 訓練 ROI，**When** 增強，**Then** 僅小幅亮度／對比、旋轉、平移（數值與機率同 Spec1），影像與遮罩同步轉換；目標牙新增截斷時取消整次幾何變換並保留亮度／對比；禁止縮放、翻轉、Mosaic、MixUp、隨機裁切與彈性變形。
3. **Given** 驗證／測試 ROI，**When** 處理，**Then** 無隨機增強。
4. **Given** 完成建置，**When** 產生報告，**Then** 含資料版本、配對與隔離統計、疊圖範例、標註審閱狀態與限制。

### Edge Cases

- 偵測框外擴後超出原圖：超出部分補背景並記錄；原圖已截斷的牙齒保留可見標註，增強不得再新增截斷。
- 框比對應牙偏小，外擴 10% 後牙齒仍被框切掉：保留可見遮罩並標記「ROI 內牙齒被截斷」，不擴大框。
- 目標牙遮罩在 ROI 內為空或面積極小：隔離並記錄。
- 鄰牙部分落入 ROI：標為背景，並記錄此現象以供後續分析。
- 同一多邊形與多個框的 IoU 都達門檻：依一對一規則處理，無法唯一決定者隔離。
- 偵測框來源或審閱狀態未知：照實記錄，不沿用 tooth 多邊形的確認狀態。
- 缺檔、損毀、座標越界、框退化（寬或高為零）：隔離並記錄原因。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: MUST 以 `data/detection_dataset/`（YOLO 偵測框）為 ROI 來源、`data/seg_dataset/`（COCO tooth 多邊形）為標籤來源；逐檔檢查可解碼性、位元深度、通道、尺寸、框與多邊形合法性，並確認兩邊影像與子集一一對應，保存資料版本與排除原因。
- **FR-002**: MUST 將每個偵測框與 IoU 最高、且達最低門檻的 tooth 多邊形配對（IoU 以框與多邊形外接框計算）；一對一；最佳與次佳過於接近、多框競爭或低於門檻者隔離並記錄 IoU、次佳 IoU 與原因。門檻、歧義容差於規劃登錄，並在建置前固定；不得依測試結果調整。
- **FR-003**: MUST 產生只含目標牙的二元遮罩：目標牙多邊形為前景，鄰牙與 Metal 皆為背景；Metal 不獨立成類。
- **FR-004**: MUST 將偵測框向外擴 10% 後裁出，超出原圖處補背景，再等比例 letterbox 成 256×256（補邊為背景，遮罩縮放不產生新類別值），並記錄原圖座標、外擴、縮放與補邊，可還原至原圖。
- **FR-005**: 影像前處理 MUST 僅用固定 CLAHE（不使用 NLM、USM），已確認 8-bit 影像採固定線性強度映射、不做逐張 min–max；固定處理不得改動遮罩；其他位元深度須先檢查。參數於訓練前登錄。
- **FR-006**: 資料增強 MUST 與 Spec1 相同：僅小幅亮度／對比、旋轉、平移，禁止隨機縮放、翻轉、Mosaic、MixUp、隨機裁切與彈性變形；強度增強只作用於影像、幾何變換同步作用於影像與遮罩；目標牙新增截斷時取消整次幾何變換並保留亮度／對比；增強只用於訓練集。幅度、機率與順序沿用 Spec1 並於規劃登錄。
- **FR-007**: MUST 沿用既有 train／val／test，同一張原圖的所有 ROI 位於同一子集；以近重複分組查核洩漏，確認洩漏時修正並保存理由、新舊清單與種子，凍結後才可用於正式訓練；病人資訊缺失時記錄替代分群與殘餘風險。
- **FR-008**: MUST 提供可配置來源、輸出位置與參數的資料建置入口，涵蓋盤點、配對、ROI 產生、洩漏檢查與報告，並支援小樣本驗證；原始影像與標註保持不變，衍生資料保留來源與處理設定。
- **FR-009**: 每次建置 MUST 保存唯一識別碼、實際命令、程式版本及未提交變更、環境、種子、參數、資料與標註版本、切分與輸出位置；失敗保留原因，不覆寫既有結果。
- **FR-010**: MUST 產出資料驗證報告：各子集框數、多邊形數、納入／隔離數與原因分布、IoU 分布、ROI 內被截斷或含鄰牙的數量、疊圖範例（涵蓋合法、歧義隔離、截斷）與限制；公開產物不含可識別病人的資訊。
- **FR-010a**: 資料集 MUST 以 `train/`、`val/`、`test/` 三個子集目錄交付（各含 ROI 影像、遮罩與索引），並提供把全部偵測框疊在分割多邊形上的審閱疊圖，供人工核對配對。
- **FR-011**: 本功能 MUST NOT 訓練任何模型或宣稱模型表現；範圍僅為資料集與其驗證。

### Key Entities *(include if feature involves data)*

- **來源影像與標註版本**: 原影像、偵測框、tooth 多邊形、來源與審閱狀態、有效性。
- **框—多邊形配對**: 偵測框、候選多邊形、IoU、次佳 IoU、配對狀態、隔離原因。
- **ROI 樣本**: 影像 ROI、單牙遮罩、原圖座標、外擴／縮放／補邊紀錄、是否截斷、鄰牙是否入框。
- **切分清單**: 子集、分組、洩漏檢查與修訂紀錄。
- **資料集版本與報告**: 設定、統計、疊圖與限制。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 100% 納入的 ROI 可追溯至唯一的偵測框、唯一的 tooth 多邊形、原影像與子集；100% 隔離項有原因；任一多邊形不被兩個 ROI 共用。
- **SC-002**: 對齊驗證涵蓋框遮罩一致、框偏移、相鄰多牙、無對應多邊形、多框競爭、框超出原圖、原圖已截斷七類案例，結果皆符合既定規則；遮罩無新增標籤值；ROI 控制點還原誤差每軸不超過 1 個原圖像素。
- **SC-003**: 同一原圖 ROI 跨子集數為零，已知近重複跨子集組數為零（資訊不足者明示限制）。
- **SC-004**: 增強驗證涵蓋合法變換與新增截斷兩類，100% 新增截斷案例取消幾何變換並保留亮度／對比；驗證與測試 ROI 為零隨機增強。
- **SC-005**: 研究人員僅憑報告與資料版本即可查證各子集 ROI 數、隔離原因分布與 ROI 內截斷／鄰牙比例，並重建同一資料集（相同輸入與種子得相同清單）。

## Assumptions

- 2026-10-12 初步盤點：兩邊皆為同一批 101 張影像、切分一致（61／20／20）；偵測框 273 個、tooth 多邊形 233 個，其中 35 張影像兩邊牙數不同；以 IoU ≥ 0.5 估計約 232 個框可配對、其餘約 41 個框無可信對應。此為估計，正式數字以建置報告為準。
- 預設最低 IoU 為 0.5、最佳與次佳 IoU 差至少 0.1，皆可於規劃調整並在建置前固定；調整只能依訓練／驗證資料或已知合成案例，不得參考測試結果。
- 偵測框來源與審閱狀態尚未確認（`data/detection_dataset` 說明僅稱標籤複製自 `data/tooth_detection/`），本版記為「未知」；tooth 多邊形標註為人工且經專家確認（使用者 2026-10-12 確認，適用目前資料版本），兩者狀態分開記錄。
- ROI 尺寸 256×256 與「每側外擴 10%」為使用者已確認值（2026-10-12）。
- 依賴 [spec1](../001-train-tooth-detection/spec.md) 的增強政策與 [spec2](../002-train-unet-baseline/spec.md) 的遮罩、截斷規則與驗證方式；不採用 spec1／spec2 的 NLM 與 USM。
- 不納入：模型訓練與評估、偵測框修正或重新標註、多牙 ROI、牙位辨識、Metal 獨立分割、CRR 計算、部署。資料來源授權與病人資訊尚待盤點。

## Research Integrity *(mandatory for data/model features)*

原始影像、偵測框與多邊形保持不變，衍生 ROI 與遮罩保留來源框、來源多邊形與轉換設定。tooth 多邊形為人工且經專家確認（使用者 2026-10-12 確認，記錄來源、日期與資料版本）；偵測框狀態另記為未知，配對得到的遮罩品質受兩來源不一致影響，報告須揭露隔離比例與其可能造成的選擇偏差（被隔離的框可能集中於難例）。

資料切分沿用既有目錄分割，並以近重複分組與同圖 ROI 不跨子集防止洩漏；缺病人資訊不得宣稱已排除病人層級洩漏。增強參數與配對門檻不得由測試集決定；從資料擬合的處理參數僅能使用訓練集（本功能的 CLAHE 為固定參數，不從資料擬合）。

本功能不計算模型指標；報告僅含資料統計（框數、多邊形數、IoU 分布、隔離與截斷比例），並定義其單位與母體（以 ROI 為單位，子集為母體）。公開產物不含可識別病人的資訊。
