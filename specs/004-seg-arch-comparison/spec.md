# Feature Specification: 牙齒分割模型架構比較（對照 baseline U-Net）

**Feature Branch**: 沿用目前分支；本次未建立分支

**Created**: 2026-10-12

**Status**: Ready for planning

**Input**: User description: "Segmentation 在幫我找幾個模型架構訓練，和 baseline U-Net 比較"

## Clarifications

### Session 2026-10-12

- Q: 比較在哪份資料上進行？ → A: 預設沿用目前 baseline 所用的單顆牙 ROI 資料集（spec 003，train／val／test＝138／48／46 個 ROI、同一張原圖的 ROI 同子集）與同一套評估定義，不另建資料。
- Q: 候選架構由誰挑？ → A: 使用者最終指定本次只比較 2 個候選：**U-Net++、Attention U-Net**，連同 baseline U-Net 共 3 個模型。DeepLabV3+ 與 SegFormer 曾被提及，本次明確不納入，留待後續。規劃階段只登錄兩個候選的具體實作與規模並說明取捨。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 在同一把尺上重現 baseline 並固定比較規則 (Priority: P1)

研究人員能確認 baseline U-Net 在比較用的流程下可被重現，並事先登錄所有候選模型共用的資料、切分、訓練預算、選模規則與評估定義，使任何差異都來自架構而非流程。

**Why this priority**: 資料量小、單次結果變異大；沒有共同基準與事先固定的規則，比較結論沒有意義。

**Independent Test**: 以多個種子重跑 baseline，核對結果落在既有單次結果合理範圍內，並檢查登錄的比較協議涵蓋資料、切分、預算、選模與指標。

**Acceptance Scenarios**:

1. **Given** 既有 baseline 與固定的資料切分，**When** 以多個種子重跑，**Then** 得到每個種子的驗證選模結果與測試前的種子變異估計，並與既有單次結果並列。
2. **Given** 一份比較協議，**When** 凍結，**Then** 內含資料版本、切分清單、訓練與增強設定、停止與選模規則、閾值、種子數與統計方法；之後修改須留下理由與新舊版本。
3. **Given** 任何候選模型，**When** 訓練，**Then** 只使用 train 更新權重、只用 val 選模；test 不參與調參、閾值或選模。

---

### User Story 2 - 訓練並評估候選架構 (Priority: P2)

研究人員能取得數個設計取向不同的候選架構，在相同協議下各訓練多個種子，並保留完整的可追溯紀錄與權重。

**Why this priority**: 這是比較的資料來源，依賴 US1 的協議。

**Independent Test**: 以小樣本讓每個候選完成資料讀取、前向、訓練、驗證與權重載入，再核對正式執行的紀錄完整性。

**Acceptance Scenarios**:

1. **Given** 使用者指定的兩個候選，**When** 登錄，**Then** 每個候選有名稱、設計取向（U-Net++：巢狀密集跳接；Attention U-Net：跳接處的注意力閘門）、具體實作、來源與授權、參數量、初始化方式，並符合單張 8 GB 顯示卡可訓練。
2. **Given** 一個候選與一個種子，**When** 訓練完成，**Then** 保存最佳與最後權重、學習曲線、驗證指標、選模依據與完整重現資訊；失敗或資源不足時保留原因，不標示為成功。
3. **Given** 兩個候選與 baseline，**When** 訓練，**Then** 全部使用隨機初始化並以相同的通道規模與訓練配方為出發點；若日後加入預訓練變體，須另列為次要組、標明權重來源與授權，不與主要組混合排名。

---

### User Story 3 - 公平比較與可查證的結論 (Priority: P3)

研究人員能取得各模型的分割表現、成本與統計不確定性，並得到「是否有證據顯示某架構優於 baseline」的誠實結論與下一步建議。

**Why this priority**: 比較的價值在於可查證的結論，而不是單一最高數字。

**Independent Test**: 以已知預測與真值核對指標與配對差異計算，並以固定權重對 test 一次性產出比較報告。

**Acceptance Scenarios**:

1. **Given** 各模型各種子的固定權重，**When** 在 test 上評估一次，**Then** 每個模型報告 Dice（主要）、IoU、precision、recall、邊界誤差（輔助）的各種子值、平均與標準差，並附參數量、峰值 GPU 記憶體與訓練與推論時間。
2. **Given** 候選與 baseline 的逐 ROI 結果，**When** 比較，**Then** 以配對差異與以原圖為單位重抽樣的信賴區間表示，並說明差異是否超出種子間變異。
3. **Given** 比較結果，**When** 撰寫結論，**Then** 僅在信賴區間排除零且超出種子變異時才稱「有證據優於 baseline」，否則寫「未見可證實差異」；列出限制並提出至少一項有案例支持的後續建議。
4. **Given** 錯誤案例，**When** 檢視，**Then** 可看到各模型在同一批困難 ROI（如牙根漏分、貼近邊界、含鄰牙）上的表現差異。

### Edge Cases

- 某候選在 8 GB 顯示卡上無法以預設批次訓練：記錄原因，只允許在協議內預先登錄的方式調整（如批次大小、梯度累積），並標示；仍無法訓練則列為未完成，不從表中消失。
- 某個種子訓練發散或失敗：保留紀錄並納入統計說明，不得挑選成功的種子。
- 候選與 baseline 的參數量差距很大：報告參數量與成本，不把容量差異當成架構優劣的證據。
- test 僅 46 個 ROI（約 20 張原圖）：同圖 ROI 非獨立，統計須以原圖為單位；樣本小時明示檢定力有限。
- 某模型的驗證分數明顯優於 test：揭露可能的驗證選擇偏差，不調整 test 規則。
- 若任何人使用 test 結果修改了設定：記錄並以新的未使用資料確認，才能做確認性結論。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: MUST 以目前的單顆牙 ROI 資料集（spec 003）及其既有 train／val／test 為比較資料，沿用 baseline 的前處理、訓練期增強規則與評估定義（每個 ROI 於其原圖解析度計算，補邊不計）；比較期間資料版本與切分凍結。
- **FR-002**: 候選架構 MUST 為使用者指定的 U-Net++ 與 Attention U-Net（另含 baseline U-Net）；規劃階段須為每個候選登錄具體實作與規模、來源、授權、參數量與取捨理由，並在正式訓練前取得使用者確認；每個候選須能在單張 8 GB 顯示卡訓練。若某候選無法在該資源下訓練，須記錄並由使用者決定處理。本次不納入其他架構。
- **FR-003**: MUST 在訓練前登錄比較協議：訓練預算（最大訓練輪數、停止條件）、優化與損失設定、批次與資源處理規則、選模規則（沿用驗證 Dice 最高、同值選較早輪）、二元閾值 0.5、種子清單與統計方法；所有模型共用同一協議，不得依測試結果更改。
- **FR-004**: MUST 對 baseline 與每個候選各至少訓練 3 個種子（預設 3），並保存每個種子的結果；不得只報告最佳種子。
- **FR-005**: 本次比較 MUST 全部使用隨機初始化；預訓練變體不在本次範圍，若日後加入須記錄權重來源與授權，並與主要組分開呈現。
- **FR-006**: MUST 僅以 train 更新權重、以 val 選模；test MUST 僅在協議凍結且選模完成後評估一次；任何對 test 的調整須記錄並使確認性結論失效。
- **FR-007**: 每次執行 MUST 保存唯一識別碼、實際命令、程式版本與未提交變更、環境與裝置、種子、完整設定、資料與切分版本、初始化與權重來源、權重識別與雜湊、產物位置；失敗保留原因，不覆寫既有結果；裝置非確定性須記錄。
- **FR-008**: 評估 MUST 報告 Dice（主要，全體 ROI 像素累計）、IoU、precision、recall、逐 ROI 平均與逐 ROI 結果，以及至少一項邊界誤差指標；零分母、空遮罩與排除規則於評估前固定；補邊不納入評估。
- **FR-009**: MUST 為每個模型報告參數量、峰值 GPU 記憶體、單次訓練時間與每個 ROI 的推論時間，並說明量測條件。
- **FR-010**: MUST 以原圖為抽樣單位（同圖 ROI 不獨立）估計配對差異的信賴區間，並比較差異與種子間變異；結論措辭須符合 US3 的證據門檻。
- **FR-011**: MUST 提供可配置資料、輸出、種子與模型選擇的執行方式，涵蓋小樣本驗證、單一模型訓練、驗證選模、固定 test 評估與比較報告；既有 baseline 流程不得被破壞。
- **FR-012**: MUST 產出比較報告：協議、候選清單與取捨、各模型各種子結果、平均與標準差、配對差異與信賴區間、成本表、錯誤案例比較、限制與未量測項目；報告不得宣稱臨床能力或穩健性超出實測。

### Key Entities *(include if feature involves data)*

- **候選架構**: 名稱、設計取向、來源與授權、參數量、初始化方式與來源。
- **比較協議**: 資料與切分版本、訓練預算、選模與停止規則、閾值、種子清單、統計方法、凍結時間。
- **實驗執行**: 候選×種子的識別碼、設定、環境、狀態、學習曲線、最佳與最後權重。
- **評估結果**: 逐 ROI 預測指標、各模型彙總、配對差異與信賴區間、成本量測。
- **比較報告**: 結論、證據連結、限制與後續建議。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: baseline 與每個候選皆完成至少 3 個種子的正式訓練、驗證選模與一次性 test 評估；每次正式執行 100% 具備 FR-007 的重現資訊，失敗的執行亦有紀錄。
- **SC-002**: 所有模型使用同一份凍結的資料、切分、預算與評估定義，協議凍結後對 test 的使用次數為一次，並有紀錄可查。
- **SC-003**: 對每個模型報告各種子的 Dice、IoU、precision、recall 與邊界指標，每項為有效數值或明確的未定義原因；同時列出參數量、記憶體與時間成本。
- **SC-004**: 每個候選相對 baseline 都有配對差異與信賴區間，且結論明確區分「有證據優於」、「未見可證實差異」與「有證據較差」。
- **SC-005**: 研究人員僅憑報告與資料版本即可追溯任一模型的設定、切分與權重，並能重建同一比較（相同協議與種子得到同一份清單與設定）。
- **SC-006**: 錯誤案例分析涵蓋至少三類（牙根漏分、含鄰牙、貼近邊界或被截斷），各模型在同一批案例上並列展示（未發生者標示零例）。

## Assumptions

- 預設比較任務為單顆牙 ROI 二元分割；整張影像、多類別、instance 分割與牙位辨識均不納入。
- 候選為使用者指定的 2 個（U-Net++、Attention U-Net），另含 baseline，共 3 個模型；DeepLabV3+、SegFormer 不納入本次。
- 三者同屬 U-Net 家族，差別在跳接結構；以 baseline 的基礎通道規模為起點，但 U-Net++ 與注意力閘門會增加參數量與計算量。報告須列出參數量，容量差異不得當成架構優劣的證據；若要控制容量，另以預先登錄的等參數量變體作次要比較。
- 預設無預訓練權重，因此不存在主要組與預訓練次要組之分；預訓練相關需求僅保留為日後擴充的規範。
- 預設 3 個種子；若資源允許可增加，但不得少於 3；種子數與清單於協議中固定。3 個模型 × 3 個種子共 9 次訓練，每次約數十分鐘（baseline 單次約 10–25 分鐘）。
- baseline 沿用既有 U-Net 設定；既有單次結果（test Dice 約 0.93）僅作參考，正式比較以協議下的多種子重跑為準。
- 若需公平調參，所有模型使用相同且事先登錄的預算；預設不做逐模型調參，以固定配方比較架構本身。
- 依賴 [spec 002](../002-train-unet-baseline/spec.md) 的訓練與評估方法，以及 [spec 003](../003-tooth-roi-seg-dataset/spec.md) 的資料集；資料授權與病人資訊尚待盤點，多邊形標註為人工且經專家確認（使用者 2026-10-12），偵測框審閱狀態未知，被隔離的 41 個框（分割標註缺漏）不在資料內。
- 不納入：DeepLabV3+、SegFormer 等其他架構、新資料集、重新標註、CEJ／CRR 計算、部署、模型壓縮、集成模型（ensemble）。

## Research Integrity *(mandatory for data/model features)*

原始影像與標註保持不變；訓練與評估只讀取既有衍生資料。所有模型共用同一份凍結切分，同一張原圖的 ROI 不跨子集；缺病人資訊，不得宣稱已排除病人層級洩漏。增強只用於訓練集；從資料擬合的處理參數僅能使用訓練集。test 不得用於調參、閾值或選模，違反者須記錄並使確認性結論失效。

指標以 TP、FP、FN 表示 ROI 內牙齒像素正確預測、背景誤判為牙齒與漏分：Dice = 2TP/(2TP+FP+FN)，IoU = TP/(TP+FP+FN)，precision = TP/(TP+FP)，recall = TP/(TP+FN)，單位 0–1；主要彙總為全體 ROI 的像素累計，逐 ROI 平均另列，兩者不混用；零分母標示未定義。報告須列出評估子集、樣本量（ROI 與原圖數）、有效像素、標註審閱狀態、閾值、協議版本與各執行的識別碼。

單一資料集、小樣本（test 約 20 張原圖）下的差異屬探索性；未達證據門檻的差異不得寫成優劣。公開產物不含可識別病人的資訊（原圖角落可能燒錄姓名與日期，疊圖不可公開）。不得宣稱臨床診斷能力；未執行的量測（如更多種子、外部資料）明示未量測。
