# Feature Specification: ML 研究目錄分工與文件規範

**Feature Branch**: `main`（沿用目前分支；本次未建立新分支）

**Created**: 2026-10-07

**Status**: Draft

**Input**: User description: "幫我完善 research/、src/、reports/ 的 README.md，並寫下 constitution、specify 的內容。"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 理解目錄分工 (Priority: P1)

研究者閱讀三個目錄的說明後，能決定實驗流程、共用函式與結果各自應放在哪裡，
並分辨目前已有的功能與後續規劃。

**Why this priority**: 避免將實驗、核心實作與產物混在一起，降低接手與維護成本。

**Independent Test**: 只閱讀三份目錄說明，將資料比較實驗、polygon 驗證函式及
評估圖表分別歸類，並對照工作目錄核對現況。

**Acceptance Scenarios**:

1. **Given** 新研究者需要加入一個模型比較實驗，**When** 閱讀目錄說明，
   **Then** 能找到實驗編排、共用實作與結果保存位置。
2. **Given** 目錄尚無實作或舊文件引用已不存在的功能，**When** 閱讀說明，
   **Then** 能辨識空白占位與現有入口，不會把規劃當成已完成能力。

### User Story 2 - 留下可重現的實驗紀錄 (Priority: P2)

研究者可依文件提供的紀錄格式，寫下假設、資料切分、執行設定、結果與限制，
讓其他研究者能追溯結論及比較條件。

**Why this priority**: 僅有指標或圖表不足以重現實驗，也無法確認比較是否公平。

**Independent Test**: 以一個假想實驗填寫紀錄，檢查是否涵蓋資料、命令、版本、
環境、種子、權重、評估範圍、結果與限制；不需要實際訓練模型。

**Acceptance Scenarios**:

1. **Given** 一次實驗已執行，**When** 依文件整理結果，
   **Then** 能留下唯一執行識別碼與足以追溯輸入、設定及輸出的資訊。
2. **Given** 某項指標尚未計算或資料無法分享，**When** 撰寫報告，
   **Then** 明確標示未量測或存取限制，不以猜測數字或缺失值冒充結果。

### User Story 3 - 讓後續需求遵循共同原則 (Priority: P3)

維護者可使用專案憲章審查新的需求與計畫，確認目錄分工、重現性、
資料完整性、標註狀態及驗證責任一致。

**Why this priority**: 將本次文件約定轉成後續可以檢查的規則。

**Independent Test**: 檢查憲章與規格、計畫、任務模板，確認每項原則有相應檢查入口。

**Acceptance Scenarios**:

1. **Given** 新計畫涉及資料或模型，**When** 完成原則檢查，
   **Then** 必須說明資料來源、切分、標註狀態、結果紀錄與驗證方式。
2. **Given** 變更只涉及文件，**When** 選擇驗證方式，
   **Then** 核對內容、連結與命令即可，不要求執行完整模型訓練。

### Edge Cases

- 說明文件拼字錯誤：統一為標準名稱，保留原說明的實驗簡潔與共用函式分工意圖。
- 子目錄為空：清楚標示尚未實作，與建議用途區分。
- 權重或本機資料不存在：範例說明前置條件，不宣稱命令已完成推論。
- 部分舊測試引用不存在的模組：記錄限制，不把完整測試套件寫成已通過。
- 結果目錄被版控忽略：保留說明文件的追蹤能力，大型產物仍需外部保存。
- 未提供病人分組資訊：要求記錄替代切分方式及殘餘洩漏風險。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 三個目錄 MUST 各有一份可閱讀的標準說明文件，定義目的、內容與責任。
- **FR-002**: 說明 MUST 區分實驗編排、共用實作與輸出保存，並提供互相導覽的連結。
- **FR-003**: 說明 MUST 對應目前目錄及入口，明確標示空白占位與缺失功能。
- **FR-004**: 研究說明 MUST 要求紀錄假設、baseline、比較變因及固定切分。
- **FR-005**: 結果說明 MUST 提供包含資料版本、切分、執行命令、程式版本、環境、
  種子、參數、權重來源、評估範圍、結果及限制的紀錄格式。
- **FR-006**: 說明與憲章 MUST 定義原始資料保存、分組切分、訓練限定的擬合與增強、
  測試集隔離及偽標註審閱責任。
- **FR-007**: 現有使用範例 MUST 說明所需資料與權重、執行位置及主要輸出，
  不宣稱尚未提供的資源已存在。
- **FR-008**: 憲章 MUST 有具體原則、治理與版本日期，且後續規格、計畫、任務的
  檢查方式 MUST 與原則一致。
- **FR-009**: 說明文件 MUST 可納入版控；大型結果及私人影像 MUST 維持獨立保存。
- **FR-010**: 文件整理 MUST 保留既有實作及使用者尚未提交的工作，並將未完成的
  程式遷移與模型驗證列為範圍外。

### Key Entities *(include if feature involves data)*

- **目錄說明**：目錄目的、責任、現況、入口與相關文件。
- **實驗紀錄**：一次執行的識別碼、假設、輸入與設定、結果及限制。
- **研究產物**：指標、圖表、模型輸出與審閱資訊，對應一份實驗紀錄。
- **專案憲章**：共同原則、適用範圍、驗證責任與修訂規則。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 三份目錄說明均存在，且所有實際文件連結可解析。
- **SC-002**: 讀者可依說明正確歸類實驗入口、共用函式與評估圖表三種工作。
- **SC-003**: 實驗紀錄格式覆蓋 FR-005 的全部資訊；未量測與存取受限情況有明確寫法。
- **SC-004**: 完成的憲章沒有未填佔位符，三種後續工作模板均與其原則一致。
- **SC-005**: 文件對現有入口與空目錄的描述全數與工作目錄一致，且無虛構評估結果。

## Assumptions

- 將使用者的「READMD.md」視為標準 README 文件，「constitution specify」視為
  建立專案憲章及本次文件整理規格；不擴張為完整 CRR 系統的功能設計。
- 使用目前的研究分工意圖：實驗流程簡潔，共用或複雜函式移交核心實作。
- 本次只整理文件及其保存規則，不搬移模型程式、不修復舊測試、不重新訓練，
  不產生實際資料切分或研究結果。
- 根目錄及其他既有文件、程式仍可能保留歷史路徑；本次說明須提示這個限制。

## Research Integrity *(mandatory for data/model features)*

本 feature 不執行資料或模型流程，因此不新增資料集、切分、模型或量測結果。
文件必須描述來源追溯、分組切分、防洩漏、標註審閱與指標誠實的要求，
並依專案憲章區分既有能力與後續研究約定。
